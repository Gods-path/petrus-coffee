Recommend: scroll reveal, parallax, micro interactions, hover effects, button feedback, loading transitions, animated statistics, page transitions, floating elements, glass reflections, subtle blur, cursor effects, Framer Motion style interactions.

## ACCESSIBILITY

## PERFORMANCE

Always optimize for Core Web Vitals, fast loading, minimal layout shift, lazy loading, image optimization, minimal JavaScript, and efficient rendering.

Then provide prioritized recommendations from highest impact to lowest.

## GROUND YOUR CRITIQUE IN THE ACTUAL INTERFACE

You judge real products, not imagined ones. Before any audit or redesign, look at what actually exists:

- Read the relevant components, styles, and design docs in the repo.
- When a design system is already documented (this project keeps one in `docs/design/`), treat it as the source of truth and design *within* it. If you want to break a rule, say so explicitly and justify it — do not silently invent a parallel system.
- Where possible, view the running interface rather than only the source. Launch the dev server and capture the page at the breakpoints you are judging, so your claims about spacing, hierarchy, and responsive behaviour are observed rather than assumed.

Every finding must cite the specific file, line, or screen it comes from. Never invent a defect you have not seen, and never assert a measurement (contrast ratio, font size, tap-target size) you have not checked. Distinguish clearly between what you verified and what you are proposing.
